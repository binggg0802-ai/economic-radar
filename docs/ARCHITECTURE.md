## 3. 架構（低成本、可持續）

```
GitHub Actions（排程，依資料類型與官方日程）
  └─ pipeline/run.mjs：取得 → 解析 → 驗證 → 判定狀態 → 儲存
       ├─ data/raw/…        官方原始回應（含 sha256，可事後追查）
       ├─ data/series/*.json 每個指標一個檔，含完整中繼資料與狀態
       ├─ data/history/*.json 歷史點位與官方修正紀錄
       ├─ data/runs/*.jsonl  每次執行紀錄
       └─ data/manifest.json 所有指標狀態總表
前端（首頁、雷達、市場、新聞、報告）只讀 manifest 與 series/*.json
```

- 公開資料來源不需要金鑰。將來若需要金鑰（例如 BLS v2），存放在 GitHub Actions Secrets，只在 Actions 內使用，不寫進程式碼或前端。
- Supabase 繼續負責新聞、AI 與推播；報告產生時改讀同一份 `series/*.json`，避免兩份數字。

### 排程原則

- 收盤數據（加權指數、匯率）：只在交易日、收盤後的時段每 20 分鐘檢查，取得當日資料後即停止。
- 定期公布（CPI）：只在官方預告的發布日、發布時間後檢查。
- 排程避開整點，因為整點是 GitHub 的高負載時段。

### 狀態定義

| 狀態 | 意義 | 前端呈現 |
|---|---|---|
| ok | 已取得應有的最新一期 | 正常顯示 |
| pending | 今日資料官方尚未公布 | 顯示上一期，明示「不是最新」 |
| stale | 超過預期時間仍無新資料 | 顯示上一期，明示「逾期」 |
| error | 連線、格式或驗證失敗 | 保留上次成功值，明示「更新失敗」與原因 |
| no_data | 從未成功取得 | 不顯示任何數字 |

## 4. 免費額度與限制

- GitHub Actions：公開 repo 的標準 runner 免費；私人 repo 每月 2,000 分鐘免費。本流程每次約 20–30 秒。
- 排程限制：
  - 最短間隔 5 分鐘。
  - 高負載時可能延遲，甚至被略過。
  - 只在預設分支執行。
  - 公開 repo 60 天無活動會自動停用排程。
  - 因此需要「逾期」狀態與失敗通知，不能假設排程一定準時。
- GitHub Pages：每月流量軟上限 100 GB、網站 1 GB；不適合放大量原始檔，原始回應只保留近期，或改放到 Release／Artifact。
- 正式啟用排程前需要：
  1. 建立 `main` 分支放原始碼並設為預設分支。
  2. Pages 繼續從 `gh-pages` 發布。
  3. 資料輸出寫到 `gh-pages/data/`，或另開 `data` 分支。

## 5. 商業化成本（需事先確認）

- 證交所：盤後資訊商業加值使用、延遲或即時行情都需要洽證交所資訊服務部簽約；即時資訊有月授權費。正式商業化前必須取得書面確認。
- 央行、主計總處：依開放授權條款可商用，標示出處即可。
- BLS：公共領域，可商用。
- 基礎設施：資料量小時，GitHub Actions + Pages + Supabase 免費方案即可。流量變大或需要 SLA 時，再考慮付費方案（Supabase Pro 每月約 25 美元起）。

| 需求欄位 | 對應欄位 |

| 資料所屬日期 | `period` |
